================================================================================
           NEXTCV — PIPELINE COMPLETO DE CRIAÇÃO DE CURRÍCULOS
                    Documentação Técnica Detalhada
================================================================================

Este documento descreve passo a passo como os currículos são criados na
plataforma NextCV, desde a entrada de dados do usuário até o PDF final.

================================================================================
1. VISÃO GERAL DA ARQUITETURA
================================================================================

Stack:
  • Next.js 14 (App Router) + TypeScript + Tailwind CSS
  • DeepSeek AI (modelo deepseek-chat / V3) via OpenRouter (SDK OpenAI)
  • Puppeteer + Chrome headless para geração de PDF
  • Firebase (Auth, Firestore, Storage)
  • Deploy: Vercel (com @sparticuz/chromium para produção)

Fluxo resumido:
  Formulário → API → IA DeepSeek → Pós-processamento → Validação de qualidade
  → Template HTML → Puppeteer → PDF

Arquivos envolvidos (em ordem de execução):
  1. src/app/dashboard/create-resume/page.tsx    — Frontend (formulário)
  2. src/app/api/create-resume/route.ts           — API de criação
  3. src/services/ai-resume.ts                    — Serviço de IA
  4. src/lib/resume-schema.ts                     — Schema + validação
  5. src/lib/resume-postprocess.ts                — Pós-processamento
  6. src/lib/resume-templates.ts                  — Templates HTML
  7. src/app/api/generate-pdf/route.ts            — API de geração de PDF
  8. src/utils/resume-pdf.ts                      — Utilitários client-side


================================================================================
2. ETAPA 1 — ENTRADA DE DADOS (Frontend)
================================================================================

Arquivo: src/app/dashboard/create-resume/page.tsx

O usuário tem duas opções de criação:

  A) UPLOAD DE CURRÍCULO EXISTENTE:
     - Faz upload de um PDF/DOC existente
     - O texto é extraído automaticamente
     - Campo opcional: "Vaga-alvo" para personalização
     - A IA reescreve e melhora o currículo existente

  B) CRIAR DO ZERO (formulário):
     - Nome completo, Email, Telefone
     - Localização (Cidade - Estado)
     - Link opcional (LinkedIn, portfólio, etc.)
     - Cargo/título desejado
     - Resumo profissional (textarea)
     - Experiências: empresa, cargo, início/fim, descrição
     - Formação: instituição, grau (select), área, início/fim
     - Projetos e atividades extracurriculares:
       · Tipo (Projeto Pessoal, Trabalho Voluntário, Freelance, Open Source,
         Trabalho Acadêmico, Hackathon, Outro)
       · Nome, descrição, datas, link opcional
     - Habilidades (separadas por vírgula)
     - Idiomas (separados por vírgula)

Os dados são enviados como JSON para a API /api/create-resume.


================================================================================
3. ETAPA 2 — API DE CRIAÇÃO (Backend)
================================================================================

Arquivo: src/app/api/create-resume/route.ts

Recebe:  { formData: objeto, userId: string }
Retorna: { success: true, data: resposta estruturada }

Processo:
  1. Valida presença de formData e userId (400 se ausente, 401 se sem auth)
  2. Converte formData para string JSON (se necessário)
  3. Chama createResumeFromData(stringJSON) do serviço de IA
  4. Limpa artefatos JSON da resposta (remove ```json```, etc.)
  5. Parseia e retorna o resultado


================================================================================
4. ETAPA 3 — GERAÇÃO COM IA (Serviço Principal)
================================================================================

Arquivo: src/services/ai-resume.ts

Esta é a etapa mais complexa. Implementa um pipeline de 7 passos:

────────────────────────────────────────────────────────────────
PASSO 3.1 — CACHE LOOKUP
────────────────────────────────────────────────────────────────

  • Gera um hash SHA-256 combinando:
    - Dados do usuário (normalizados: lowercase, sem acentos, sem hifens extras)
    - Versão do prompt (PROMPT_VERSION = "v6")
    - Versão do schema (SCHEMA_VERSION = "v3")
  • Se há cache válido (TTL: 7 dias), retorna sem chamar a IA
  • Economia de créditos e tempo

────────────────────────────────────────────────────────────────
PASSO 3.2 — CHAMADA À IA (DeepSeek)
────────────────────────────────────────────────────────────────

  Modelo: deepseek-chat (DeepSeek V3) via OpenRouter
  Temperatura: baixa (para respostas consistentes)
  Usa prefix caching do DeepSeek para o system prompt

  SYSTEM PROMPT (v6) — 13 regras fundamentais:

    REGRA 1 — TÍTULO PROFISSIONAL
      • Máximo 5 palavras
      • Sem adjetivos ("experiente", "dedicado")
      • Exemplos: "Desenvolvedor Full Stack", "Analista de Dados"

    REGRA 2 — RESUMO PROFISSIONAL
      • 3-5 linhas, mínimo 1 métrica quantitativa
      • Sem clichês ("busco novos desafios", "apaixonado por...")
      • Deve conectar experiência → objetivo → valor entregue

    REGRA 3 — BULLETS DE EXPERIÊNCIA
      • Formato: VERBO + CONTEXTO + RESULTADO
      • Cada bullet deve ter ação concreta e impacto mensurável
      • Mínimo 3 bullets por experiência
      • Exemplo: "Reduzi tempo de deploy em 40% implementando pipeline CI/CD"

    REGRA 4 — CATEGORIZAÇÃO DE SKILLS
      • Agrupar por categoria (Front-end, Back-end, DevOps, etc.)
      • Mínimo 2 categorias se houver 5+ skills
      • Categorias padronizadas no TECH_CATEGORY_MAP

    REGRA 5 — MÉTRICAS
      • Mínimo 3 dados quantitativos no currículo inteiro
      • Exemplos: "2+ anos", "40% de redução", "15 projetos"
      • Se dados não fornecidos, inferir de forma realista

    REGRA 6 — PRESERVAÇÃO DE DADOS (INVIOLÁVEL)
      • NUNCA inventar empresas, cargos ou formações
      • NUNCA remover experiências fornecidas pelo usuário
      • NUNCA alterar datas de início/fim
      • Apenas reescrever e melhorar o que foi fornecido

    REGRA 7 — ORDEM DAS SEÇÕES (por nível do candidato)
      • Estagiário/Júnior: Resumo → Skills → Projetos → Experiência → Formação → Idiomas
      • Pleno (padrão):    Resumo → Skills → Experiência → Projetos → Formação → Idiomas
      • Sênior/Especialista: Resumo → Experiência → Skills → Formação → Certificações → Idiomas

    REGRA 8 — EDUCAÇÃO, IDIOMAS E PROJETOS
      • Educação: NUNCA omitir, mesmo que incompleta
      • Idiomas: NUNCA omitir, incluir nível de fluência
      • Projetos: incluir tecnologias e links quando disponíveis

    REGRA 9 — SANITIZAÇÃO DE DADOS
      • Remover caracteres especiais desnecessários
      • Normalizar formatação de datas
      • Corrigir capitalização de nomes de tecnologias

    REGRA 10 — PERSONALIZAÇÃO POR VAGA
      • Se vaga-alvo fornecida, adaptar resumo e keywords
      • Destacar experiências relevantes para a vaga
      • Não inventar experiências para se encaixar

    REGRA 11 — ANTI-CLICHÊ
      • Lista de 20+ expressões proibidas
      • Substituir por descrições concretas e específicas

    REGRA 12 — CONSISTÊNCIA DE IDIOMA
      • Currículo 100% em português brasileiro
      • Termos técnicos mantidos em inglês (React, Python, etc.)

    REGRA 13 — CORREÇÃO ORTOGRÁFICA
      • Corrigir erros do usuário
      • Padronizar nomes de tecnologias (JavaScript, não "Javascrip")

  A IA também recebe:
    - O schema JSON esperado (ResumeSchema) com todos os campos
    - Instruções para retornar JSON puro (sem markdown)
    - Se há vaga-alvo, é destacada em seção separada na mensagem

  FORMATO DE SAÍDA DA IA:
    {
      "resumeData": { ...ResumeSchema },
      "generationNotes": {
        "inferredData": [...],
        "missingImpactData": [...],
        "warnings": [...],
        "candidateLevel": "júnior|pleno|sênior",
        "targetJobDetected": "..."
      },
      "qualityFlags": [...]
    }

────────────────────────────────────────────────────────────────
PASSO 3.3 — PARSE E VALIDAÇÃO DO SCHEMA
────────────────────────────────────────────────────────────────

  Arquivo: src/lib/resume-schema.ts

  Função: validateResumeSchema(data)

  Verificações:
    • data é um objeto válido
    • basics.name existe e não está vazio (OBRIGATÓRIO)
    • Todos os campos são normalizados (strings para arrays, etc.)
    • Arrays vazios são criados se ausentes (work, education, skills, etc.)

  Retorna: { valid: boolean, errors: string[], normalized: ResumeSchema }

────────────────────────────────────────────────────────────────
PASSO 3.4 — PÓS-PROCESSAMENTO DETERMINÍSTICO
────────────────────────────────────────────────────────────────

  Arquivo: src/lib/resume-postprocess.ts

  Função: postProcessResume(schema, originalText)

  Esta etapa corrige problemas que a IA CONSISTENTEMENTE ignora,
  mesmo com instruções explícitas no prompt. São 6 sub-etapas:

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.1 — CORREÇÕES ORTOGRÁFICAS FORÇADAS           │
  │                                                             │
  │ Mapa de 100+ correções para nomes de tecnologias:          │
  │   "Javascrip" → "JavaScript"                               │
  │   "Pyton" → "Python"                                       │
  │   "MYSQL" → "MySQL"                                        │
  │   "react js" → "React.js"                                  │
  │   "github" → "GitHub"                                      │
  │   "node js" → "Node.js"                                    │
  │   "type script" → "TypeScript"                             │
  │   etc.                                                      │
  │                                                             │
  │ IMPORTANTE: Correções são aplicadas campo a campo,          │
  │ PULANDO campos de URL (linkedin, github, website, url,      │
  │ repository) para não corromper links.                        │
  │                                                             │
  │ Campos processados:                                         │
  │   • basics (name, label, summary)                           │
  │   • work (position, company, highlights)                    │
  │   • education (institution, area)                           │
  │   • skills (name, category)                                 │
  │   • projects (name, description, technologies)              │
  │   • certifications (name, issuer)                           │
  │   • volunteer (role, organization)                          │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.2 — REMOÇÃO DE CLICHÊS                         │
  │                                                             │
  │ 20+ padrões regex para clichês comuns:                      │
  │   "Busco novos desafios"                                    │
  │   "Profissional dedicado/proativo"                          │
  │   "Apaixonado por tecnologia"                               │
  │   "Orientado a resultados"                                  │
  │   "Busco consolidar sua carreira"                           │
  │   etc.                                                      │
  │                                                             │
  │ Após remoção:                                               │
  │   • Limpa artefatos (pontos duplos, espaços extras)         │
  │   • Só aplica se resumo ficar com ≥80 caracteres           │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.3 — PROTEÇÃO DE NÍVEL DE IDIOMA                │
  │                                                             │
  │ Hierarquia: Nativo(5) > Fluente(4) > Avançado(3)           │
  │             > Intermediário(2) > Básico(1)                  │
  │                                                             │
  │ Se o usuário declarou "Inglês (Avançado)" e a IA retornou  │
  │ "Inglês (Intermediário)", o pós-processamento RESTAURA      │
  │ o nível original do usuário.                                │
  │                                                             │
  │ Também preserva qualificadores: "técnico", "conversação"   │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.4 — VALIDAÇÃO DE TEMPO DE EXPERIÊNCIA          │
  │                                                             │
  │ Calcula o tempo real de experiência a partir das datas      │
  │ de início/fim das experiências profissionais.               │
  │                                                             │
  │ Se a IA afirmou "5+ anos" no resumo mas as datas indicam   │
  │ apenas 3 anos, corrige para o valor real.                   │
  │                                                             │
  │ Tolerância: 6 meses (para cima)                             │
  │ Formatos aceitos: YYYY-MM, "Janeiro 2024", "01/2024"       │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.5 — RESTAURAÇÃO DE LINKS PERDIDOS              │
  │                                                             │
  │ Se o texto original do usuário continha LinkedIn ou GitHub  │
  │ e a IA não incluiu no resultado, extrai via regex:          │
  │                                                             │
  │   LinkedIn: linkedin.com/in/[...]                           │
  │   GitHub:   github.com/[...]                                │
  │                                                             │
  │ E restaura nos campos basics.linkedin / basics.github       │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SUB-ETAPA 4.6 — GERAÇÃO DE FLAGS DE QUALIDADE              │
  │                                                             │
  │ Identifica problemas estruturais (não corrige, só avisa):   │
  │   • Resumo sem métricas/números                             │
  │   • Experiências com menos de 3 bullets                     │
  │   • Bullets muito curtos (<40 caracteres)                    │
  │   • Seção de educação ou idiomas ausente                     │
  │   • Menos de 30% dos bullets com indicadores de resultado   │
  └─────────────────────────────────────────────────────────────┘

  Retorno do pós-processamento:
    {
      schema: ResumeSchema,      // Schema corrigido
      corrections: string[],     // Descrições das correções aplicadas
      qualityFlags: string[]     // Problemas identificados
    }

────────────────────────────────────────────────────────────────
PASSO 3.5 — VALIDAÇÃO DE QUALIDADE
────────────────────────────────────────────────────────────────

  Arquivo: src/lib/resume-schema.ts
  Função: validateResumeQuality(resume, generationNotes)

  Sistema de pontuação (100 pontos, começa cheio e desconta):

  PROBLEMAS CRÍTICOS (-20 pontos cada):
    • Resumo vazio ou com <100 caracteres
    • Resumo sem números/dados quantitativos
    • Experiência com menos de 3 bullets
    • Bullet com menos de 30 caracteres
    • Nenhuma skill listada
    • Clichês detectados (13 padrões)

  AVISOS (-8 pontos cada):
    • Skills sem 2+ categorias (se 5+ items)
    • Menos de 30% dos bullets com indicadores de resultado
    • Nível júnior sem projetos
    • Seção de idiomas ausente
    • Nível do candidato não identificado

  INFORMAÇÕES (-2 pontos cada):
    • LinkedIn não preenchido
    • Perfil tech sem GitHub
    • Projetos sem URLs de deploy

  Aprovação: score ≥ 70

  Auto-correções aplicáveis:
    • Categorização automática de skills (TECH_CATEGORY_MAP)
    • Adição de tempo de experiência ao resumo se sem números

────────────────────────────────────────────────────────────────
PASSO 3.6 — VALIDAÇÃO DE PRESERVAÇÃO
────────────────────────────────────────────────────────────────

  Função: validatePreservation(inputText, output)

  Compara entrada vs saída para garantir que nada foi perdido:
    • Tecnologias mencionadas no input estão no output
    • Níveis de idioma não foram rebaixados
    • Número de experiências não diminuiu
    • Termos de liderança foram preservados (líder, supervisor, etc.)

────────────────────────────────────────────────────────────────
PASSO 3.7 — RETRY CONDICIONAL
────────────────────────────────────────────────────────────────

  Se o score de qualidade < 70:
    1. Lista os problemas críticos encontrados
    2. Faz uma nova chamada à IA com prompt de correção focado
    3. Aplica pós-processamento novamente
    4. Reavalia qualidade (sem loop infinito — apenas 1 retry)

────────────────────────────────────────────────────────────────
PASSO 3.8 — CONSTRUÇÃO DA RESPOSTA FINAL
────────────────────────────────────────────────────────────────

  buildFinalResponse() monta o objeto final:
    {
      resumeData: ResumeSchema,        // Dados estruturados do currículo
      formattedText: string,           // Versão texto formatada
      qualityReport: QualityReport,    // Relatório de qualidade
      generationNotes: GenerationNotes,// Notas da IA
      postCorrections: string[],       // Correções aplicadas
      qualityFlags: string[],          // Flags de qualidade

      // Formato legado (compatibilidade frontend):
      personalInfo: {...},
      professionalSummary: string,
      experiences: [...],
      education: [...],
      skills: string[],
      languages: [...],
      certifications: [...],
      additionalSections: {...}
    }

  O resultado é armazenado no cache (TTL: 7 dias).

5. ETAPA 4 — GERAÇÃO DO HTML (Templates)
================================================================================

Arquivo: src/lib/resume-templates.ts

Quando o usuário clica para gerar/baixar o PDF, os dados JSON são
transformados em HTML. Há dois templates disponíveis:

────────────────────────────────────────────────────────────────
TEMPLATE "PROFISSIONAL (ATS)"
────────────────────────────────────────────────────────────────

  Características:
    • Single-column, 100% compatível com ATS
    • Cores: preto/cinza apenas, links em azul (#1a4d8f)
    • Fonte: Calibri, 'Helvetica Neue', Arial, sans-serif
    • Bullets: • (U+2022) em preto
    • Header: nome alinhado à esquerda, título, contato em uma linha
    • Separador: linha fina cinza (#ccc) abaixo do header

────────────────────────────────────────────────────────────────
TEMPLATE "MODERNO"
────────────────────────────────────────────────────────────────

  Características:
    • Single-column, ATS-safe com distinção visual
    • Cor de destaque: navy (#1B3A6B)
    • Barra de 4pt no topo da página
    • Títulos de seção em navy com sublinhado
    • Bullets: – (en-dash) em navy, peso normal
    • Fonte: Calibri, 'Segoe UI', Arial, sans-serif

────────────────────────────────────────────────────────────────
SISTEMA DE SIZING RESPONSIVO
────────────────────────────────────────────────────────────────

  A função estimateContentSize(data) classifica o conteúdo:

  CÁLCULO DO SCORE:
    contentScore = totalHighlights + totalProjectLines
                 + totalEducation + summaryLines

    • "large"  → contentScore > 14 OU work.length > 4
    • "medium" → contentScore > 7  OU work.length > 2
    • "small"  → restante

  TAMANHOS POR CLASSIFICAÇÃO:

  ┌──────────────┬───────────┬───────────┬───────────┐
  │              │  SMALL    │  MEDIUM   │  LARGE    │
  ├──────────────┼───────────┼───────────┼───────────┤
  │ Body font    │ 11.5pt    │ 9.5pt     │ 9pt       │
  │ Highlight    │ 11pt      │ 9pt       │ 9pt       │
  │ Name         │ 24/26pt   │ 20/22pt   │ 18/20pt   │
  │ Section title│ 13/12pt   │ 11/10.5pt │ 10.5/10pt │
  │ Section gap  │ 18pt      │ 12pt      │ 9pt       │
  │ Entry gap    │ 12pt      │ 8pt       │ 6pt       │
  │ Bullet gap   │ 4pt       │ 2pt       │ 1.5pt     │
  │ Line-height  │ 1.6       │ 1.45      │ 1.45      │
  │ Summary LH   │ 1.7       │ 1.55      │ 1.55      │
  │ Margins      │20/22/18mm │16/18/14mm │14/16/12mm │
  └──────────────┴───────────┴───────────┴───────────┘

────────────────────────────────────────────────────────────────
ORDEM DAS SEÇÕES (por nível do candidato)
────────────────────────────────────────────────────────────────

  Estagiário/Júnior:
    Resumo → Habilidades → Projetos → Experiência → Formação → Idiomas

  Pleno (padrão):
    Resumo → Habilidades → Experiência → Projetos → Formação → Idiomas

  Sênior/Especialista:
    Resumo → Experiência → Habilidades → Formação → Certificações → Idiomas

────────────────────────────────────────────────────────────────
HELPERS DO TEMPLATE
────────────────────────────────────────────────────────────────

  • fmt(date) — Formata datas: "2024-03" → "Mar 2024", "atual" → "Atual"
  • esc(text) — Escapa HTML: &, <, >, "
  • buildContactLine(basics, color) — email | telefone | cidade | LinkedIn | GitHub
  • buildProjectLinks(project, color) — Links de URL e repositório
  • renderSkillsGrouped(skills, bold) — Skills agrupadas por categoria
  • sanitizeUrl(url) — Remove espaços e barras duplicadas
  • linkTag(url, color) — Gera <a href="..."> com fallback para <span>

────────────────────────────────────────────────────────────────
SCRIPT DE AUTO-LAYOUT (JavaScript inline no HTML)
────────────────────────────────────────────────────────────────

  buildAutoFillScript() gera um <script> que roda no Puppeteer
  ANTES da captura do PDF. Garante que o conteúdo ocupe
  exatamente 1 página A4, sem espaço em branco e sem overflow.

  COMO FUNCIONA:

  1. Cria um elemento invisível com height:297mm para medir
     a altura exata de 1 página A4 em pixels

  2. Remove temporariamente min-height do .page para medir
     a altura real do conteúdo

  3. Compara conteúdo vs página disponível:

  ┌─────────────────────────────────────────────────────────────┐
  │ SE CONTEÚDO > PÁGINA (OVERFLOW → 2 páginas):               │
  │                                                             │
  │ Estratégia escalonada:                                      │
  │                                                             │
  │ a) Primeiro tenta reduzir APENAS os gaps (margens entre     │
  │    seções, entries, bullets, títulos, header).               │
  │    → Reduz até 65% dos gaps se isso for suficiente          │
  │                                                             │
  │ b) Se gaps não bastam: reduz gaps em 55% + reduz fontes     │
  │    proporcionalmente (máximo 18% de redução, floor 0.82x)   │
  │                                                             │
  │ Após o ajuste, re-mede o conteúdo.                          │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │ SE CONTEÚDO < 97% DA PÁGINA (UNDERFILL → espaço em branco):│
  │                                                             │
  │ Distribui o espaço restante como gaps extras:               │
  │                                                             │
  │ • 70% para gaps PRIMÁRIOS (entre header e seções)           │
  │   → header, seção1, seção2, ..., seçãoN-1                  │
  │                                                             │
  │ • 30% para gaps SECUNDÁRIOS (entre entries dentro de seções)│
  │   → entry1, entry2, ..., entryN-1 (dentro de cada seção)   │
  │                                                             │
  │ NUNCA altera fontes para preencher — apenas espaçamento.    │
  └─────────────────────────────────────────────────────────────┘

  RESULTADO: Currículo sempre em 1 página, sem espaço em branco,
  com fontes proporcionais e distribuição visual equilibrada.

6. ETAPA 5 — GERAÇÃO DO PDF (Puppeteer)
================================================================================

Arquivo: src/app/api/generate-pdf/route.ts

Recebe:  { resumeData: ResumeSchema, template: string, candidateLevel?: string }
Retorna: Buffer PDF com headers Content-Type e Content-Disposition

Processo:

  1. SELEÇÃO DO TEMPLATE
     → Busca no registro TEMPLATES[template] (profissional ou moderno)
     → Chama render(resumeData, { candidateLevel })
     → Recebe HTML string completa

  2. LAUNCH DO CHROME
     → Produção (Vercel/Lambda): @sparticuz/chromium (binário pré-compilado)
     → Desenvolvimento: Busca Chrome instalado no sistema:
        Windows: C:\Program Files\Google\Chrome\Application\chrome.exe
        macOS:   /Applications/Google Chrome.app/Contents/MacOS/Google Chrome
        Linux:   /usr/bin/google-chrome ou /usr/bin/chromium
     → Flags: --no-sandbox, --disable-setuid-sandbox
     → Modo: headless: "shell"

  3. RENDERIZAÇÃO
     → page.setContent(html, { waitUntil: "networkidle0" })
        ↑ Aguarda carregamento completo + execução do script de auto-layout
     → O script de auto-layout roda ANTES da captura:
        - Mede conteúdo vs página
        - Ajusta gaps/fontes se necessário
        - Garante 1 página

  4. CAPTURA DO PDF
     → page.pdf({ format: "A4", printBackground: true })
        - format: "A4" → 210mm × 297mm
        - printBackground: true → Preserva cores de fundo
        - Sem pageRanges → Captura todas as páginas (deve ser 1)

  5. RESPOSTA
     → Buffer PDF com headers:
        Content-Type: application/pdf
        Content-Disposition: attachment; filename="Nome-Curriculo.pdf"
        Cache-Control: no-store

  Sanitização do nome do arquivo:
     "João da Silva" → "Joao-da-Silva-Curriculo.pdf"
     (remove acentos, caracteres especiais, substitui espaços por hifens)
